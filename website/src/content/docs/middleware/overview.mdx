Middleware runs code around your handlers: logging, auth, CORS, limits and more. Zinc ships one small package for each under `github.com/0mjs/zinc/middleware`, and you import only the ones you use.

```go
import (
	"github.com/0mjs/zinc/middleware/cors"
	"github.com/0mjs/zinc/middleware/logger"
)

app.Use(logger.New())
app.Use(cors.New(cors.Config{AllowOrigins: []string{"https://app.example.com"}}))
```

Each package has a `New` function. It takes an optional `Config`, and any field you leave empty keeps its default, so `logger.New()` works as is. ([No Cache](/middleware/nocache/) has nothing to configure, so its `New` takes no arguments.)

What `New` returns is an ordinary `func(*zinc.Context) error`, so you can attach it to the whole app, a group, or one route. Standard `net/http` middleware works too, through [`UseHTTP`](/guide/http-interoperability/).

## A good default stack

Most JSON APIs start here. Order matters: each entry wraps everything after it.

```go
app.Use(
	requestid.New(), // 1. tag the request first, so everything can log the ID
	logger.New(),    // 2. log every request, including failures below
	recover.New(),   // 3. turn panics into 500s that the logger records
	secure.New(),    // 4. browser security headers
)
```

```bash
curl -i http://localhost:8080/hello
# HTTP/1.1 200 OK
# Cross-Origin-Resource-Policy: same-origin
# Referrer-Policy: no-referrer
# X-Content-Type-Options: nosniff
# X-Frame-Options: SAMEORIGIN
# X-Request-Id: 83d4da64e6fcaaf8da8484c63a3aa52c
# X-Xss-Protection: 0
```

```text
2026/09/28 01:22:59 INFO REQUEST method=GET uri=/hello route=/hello status=200 latency=21.042µs host=localhost:8080 bytes_in="" bytes_out=5 user_agent=curl/8.7.1 remote_ip=::1 request_id=83d4da64e6fcaaf8da8484c63a3aa52c
```

A handler that panics still gets a log line, at `ERROR` with the message `REQUEST_ERROR` and an `error` attribute, and the client gets a `500`.

Add [CORS](/middleware/cors/) when browsers on other origins call the API, [Context Timeout](/middleware/timeout/) to bound slow requests, and an auth middleware on the groups that need it.

## Put middleware where it belongs

On the app, for every request:

```go
app.Use(requestid.New(), logger.New())
```

On a group, for a family of routes:

```go
api := app.Group("/api", keyauth.New(keyauth.Config{Validator: validateKey})) // validateKey: your keyauth.Validator
```

On one route:

```go
app.Post("/exports", limiter.Concurrency(2), startExport)
```

## Skip middleware for some requests

`zinc.Skip` runs a middleware unless your function returns `true` for the request:

```go
app.Use(zinc.Skip(func(c *zinc.Context) bool {
	return c.Path() == "/healthz"
}, logger.New()))
```

Here, load balancer probes to `/healthz` don't fill your logs.

## Contrib

Middleware that needs a third-party library lives in a separate repository, [`github.com/0mjs/contrib`](https://github.com/gozinc/contrib), so Zinc's own module needs nothing beyond the standard library. Each contrib package is its own Go module, versioned on its own, and you `go get` it separately:

| Package | Depends on |
|---|---|
| [`github.com/0mjs/contrib/jwtauth`](/middleware/jwtauth/) | `github.com/golang-jwt/jwt/v5` |

[OpenTelemetry](/middleware/open-telemetry/) is neither a Zinc package nor a contrib one: it's a recipe that uses the official `otelhttp` package, which works with Zinc because a Zinc app is an `http.Handler`.
